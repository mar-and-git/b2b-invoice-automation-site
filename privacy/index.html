Privacy Policy

Applies to the privately operated B2B Invoice Automation Windows application and its optional connection to the owner's Gmail account.

Last updated: 10 November 2026

1. Who operates the application

B2B Invoice Automation is a locally operated tool used to manage the owner's business financial documents. It is not currently offered as a public multi-user service. For questions about this policy or data handling, contact mariuszsadlo.analytics@gmail.com.

2. Google data accessed

With the account owner's consent, the application uses the Gmail API scope https://www.googleapis.com/auth/gmail.readonly. This scope technically permits viewing email messages, attachments and certain Gmail settings throughout the authorized mailbox. The application's intended normal workflow limits searches and retrieval to relevant financial-document messages from configured sources (currently BP fuel-document emails).

For matching messages, it may process message identifiers, sender and recipient details, subject, date, authentication metadata, MIME part information, attachments and their document content. The application does not request Gmail permissions to send, delete, archive, label or otherwise change email.

3. Purposes of use

Google user data is used only to locate the relevant supporting documents; verify authenticity and identity; extract document data such as invoice number, transaction date, fuel type and quantity; identify duplicates; correlate the evidence with existing financial documents; and show the owner review results, errors or exceptions. Email attachments are evidence associated with an existing invoice, not automatically a new accounting transaction.

4. Where and how data is handled

The integration runs within the owner's local Windows application. OAuth authorization is performed through Google's browser consent flow. Local OAuth credentials and refresh tokens are protected using Windows DPAPI CurrentUser and kept outside the code repository. Document-handling components apply controlled parsing and integrity checks, including file hashes. Supporting attachment content, document identifiers and technical evidence may be retained locally as required for matching, review and audit.

The application may correlate information derived from Gmail attachments with the owner's separately configured invoice and document sources. It does not need to publish email messages or attachments to this public website or to GitHub.

5. Sharing and limited use

The application is designed for the owner's financial-document workflow. Google user data obtained through Gmail is not sold, used for advertising, or provided to data brokers. Access is not requested for unrelated email operations. The application is not designed to transfer Gmail content to an external AI-model training service. Any future material change in data sharing or processing requires a policy update and appropriate authorization.

6. Retention and deletion

Technical evidence and downloaded business documents may be retained for document verification, duplicate prevention and the owner's audit needs. No fixed automatic deletion period is asserted for the current local workflow. The owner controls local application data and may review or delete locally retained copies subject to financial recordkeeping obligations and the application's integrity requirements. Revoking Gmail access stops future Gmail retrieval but does not automatically delete already retained local evidence.

7. Your choices and security controls

Gmail access is optional. The account owner authorizes the connection through Google OAuth and can revoke it using their Google Account's third-party connection settings. The local application may also be disconnected by disabling its Gmail integration and clearing stored authorization credentials. If permission expires or is revoked, Gmail retrieval stops; other document sources can continue independently.

8. Changes

This page describes the current privately operated Gmail READ integration. The policy will be revised if the scope of data access, storage, sharing, business purpose or intended users changes. Additional verification and disclosure may be required before any wider public or commercial distribution.
